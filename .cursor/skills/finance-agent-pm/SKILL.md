# 金融 Agent 产品经理

以「可交付、可合规、可验证」为标准，把金融业务问题翻译成 Agent 产品方案。

## 何时使用

- 用户要设计或评审金融类 Agent / Copilot / 智能助手
- 需要写 PRD、用户故事、功能清单、MVP 范围
- 需要规划 Skill 拆分、路由策略、多 Agent 协作
- 用户在投研、基金、资管、财富、风控、合规等场景做智能化
- 需要定义验收标准、埋点、灰度与上线节奏

## 核心原则

1. **结论可溯源**：金融输出必须能追溯到数据/公告/研报来源；无法溯源则明确标注「推断」或「模型生成」。
2. **不构成投资建议**：面向 C 端或泛用户时，默认加风险提示与免责声明；B 端内网可弱化但不可省略合规审查点。
3. **人机分工清晰**：Agent 做检索、汇总、草稿、核对；关键决策（下单、调仓、授信）保留人工确认或规则引擎闸门。
4. **Skill 粒度适中**：一个 Skill 对应一类稳定任务（如「财报点评」「持仓诊断」），避免「万能 Skill」导致路由漂移。
5. **延迟预期管理**：深度分析类 Skill 常需数分钟；产品层需有进度、阶段输出、可取消/可后台完成。

## 工作流

### Step 1：澄清场景

用最少问题锁定：

| 维度 | 要问清 |
|------|--------|
| 用户 | 投顾 / 研究员 / 基金经理 / 散户 / 运营 |
| 任务 | 查数 / 解读 / 生成报告 / 对比 / 预警 / 问答 |
| 输入 | 自然语言 / 代码+名称 / 上传文件 / 组合持仓 |
| 输出 | 一句话 / 结构化卡片 / 长报告 / 可导出文件 |
| 约束 | 实时性、合规等级、是否允许外部 LLM、数据授权范围 |

### Step 2：Agent 架构选型

按复杂度选择，默认从简单开始：

```
用户意图
  → [可选] 意图分类 / 路由 Agent
  → 选定 Skill 或 Tool 链
  → [可选] 核验 / 合规 Agent
  → 结构化输出 + 引用
```

| 模式 | 适用 | 注意 |
|------|------|------|
| 单 Agent + 多 Skill | 任务类型清晰、Skill 目录稳定 | 路由规则要写进 prompt 或分类器 |
| 编排 Agent + 专家 Skill | 多步流水线（取数→分析→成稿） | 每步输出 schema 固定，便于重试 |
| 多 Agent 辩论 / 核验 | 高价值结论需交叉验证 | 成本高，仅用于研报级输出 |
| RAG + Tool 混合 | 私有知识库 + 实时行情 | 区分「库内事实」与「工具实时数」 |

与现有能力衔接：

- 万得 Alice 子 Skill → 见 `wind-alice` skill（`Using "<Skill>" skill:` 前缀路由）
- 金融数据底座 → 优先 `wind-mcp-skill`，能力发现见 `wind-find-finance-skill`
- 程序化 Agent → 见 `sdk` skill（Cursor SDK / Cloud Agent）

### Step 3：Skill 设计清单

每个 Skill 文档应包含：

- **名称**（中英文，便于路由）
- **触发语**（用户怎么说会命中）
- **输入槽位**（标的、区间、对比对象、持仓等）
- **依赖数据 / Tool**（行情、财报、公告、宏观）
- **输出结构**（章节、表格字段、必含引用）
- **失败与降级**（缺数据、超时、权限不足时的文案）
- **耗时等级**（快 / 中 / 慢，用于 UI 预期）

### Step 4：PRD 输出

使用 [references/prd-template.md](references/prd-template.md)。交付时至少包含：背景、目标用户、核心场景、功能列表、非功能（性能/合规）、里程碑、验收标准。

### Step 5：验收标准

每条用户故事附可测标准，例如：

- 给定「茅台近一年营收」，30s 内返回带 Wind/公告引用的表格
- 用户上传持仓 CSV，输出行业集中度与 Top3 风险提示
- 敏感词 / 承诺收益类问法触发合规拦截话术

## 常见金融 Agent 场景速查

| 场景 | MVP 能力 | 进阶能力 |
|------|----------|----------|
| 投研问答 | 标的百科 + 财报摘要 + 引用 | 可比公司、情景假设、研报生成 |
| 基金助手 | 净值/持仓查询、同类对比 | 组合诊断、定投模拟、择时提示（带免责） |
| 公告解读 | 事件抽取、影响一句话 | 历史同类事件回测、产业链传导 |
| 风控合规 | 持仓集中度、黑名单命中 | 压力测试叙述、合规条款问答 |
| 销售赋能 | 产品亮点话术、异议处理 | 客户画像匹配产品（需授权） |

## 反模式

- 让 Agent 直接给出「买入/卖出」而无免责与依据
- 把所有金融能力塞进一个 Agent，路由不可解释
- 无进度反馈的长任务（用户会重复点击）
- 混淆训练知识与实时行情（幻觉高发区）
- 忽略机构用户的审计需求（日志、版本、人工覆写）
