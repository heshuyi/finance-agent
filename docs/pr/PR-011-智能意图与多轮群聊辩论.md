## 背景

PR-010 补齐免费数据与 LLM 子 Agent 后，用户体验仍有三处差距：

1. 意图识别依赖关键词，自然表达易误判
2. 多空辩论为并行单次陈述，缺少交锋与反驳
3. 右侧状态卡片无法呈现「投研团队协作」过程

## 用户故事

- **US-11-01**：自然语言「这只票现在能进吗」能正确识别为 `buy_analysis` 并解析标的
- **US-11-02**：买入研判可见三轮辩论：多方开篇 → 多方反驳空方 → 空方再反驳
- **US-11-03**：仲裁输出含：倾向、若买何时买及原因、若不买何时可买及原因、双方核心分歧
- **US-11-04**：群聊时间线依次展示：取数 → 核查 → 验真 → 辩论三轮 → 仲裁（带头像/角色名/时间）
- **US-11-05**：历史研判回放页可还原 `team_feed`

## 需求范围

### 必须交付

1. **智能意图**：LLM 结构化分类 + 关键词兜底（`agents/shared/intent_classifier.py`）
2. **三轮辩论**：开篇（多/空并行）→ 多反驳空 → 空反驳多（`agents/main/debate_nodes.py`）
3. **结构化仲裁**：倾向、何时买、何时可买、双方摘要、分歧、推理链（`agents/arbitrator/runner.py`）
4. **投研群聊**：`team_feed` 时间线，替换右侧侧栏（`TeamGroupChat.tsx`）
5. **持久化回放**：`team_feed` / `debate_transcript` 写入 SQLite

### 非目标

- 无限轮辩论、用户中途插话
- 文件问答、自动下单
- 替换左侧 CopilotChat

## 架构

```
prepare_task → dispatch_pipeline → [HITL?] → debate_opening → debate_pro_rebuttal
  → debate_anti_rebuttal → arbitrate → persist_task
```

各节点完成后向 `team_feed` 追加消息，经 AG-UI 同步至前端右侧群聊。

## 成本与性能

完整买入研判 LLM 调用约 **6–8 次**（意图 + 开篇×2 + 反驳×2 + 仲裁 + 验真），比 PR-010 增加约 3–4 次。Gemini 免费层可用，单次研判预计 **1–3 分钟**。

## 验收标准

- [ ] 「隆基绿能值得买吗」→ `buy_analysis`，群聊可见取数→核查→验真→三轮辩论→仲裁
- [ ] 仲裁含「何时买 / 何时可买」及双方原因
- [ ] 「成本 180 是否减仓」→ 卖出路径，多方=建议卖，空方=建议持有，同样三轮
- [ ] 无 LLM 时：意图回退关键词，辩论/仲裁降级为摘要，群聊仍展示
- [ ] `npm run build` 通过；历史研判页可回放群聊
- [ ] 无文件上传入口
